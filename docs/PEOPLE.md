## 3. 점수와 승격·강등 (`tiers.py`, 매주)
점수 0~100 = **직위·직업**(0~40: 현직 의원·판사·검사·기자 40, 고위 공직·대법관 38, 전직 의원·기업 경영진 30, 변호사·단체장 25, 연예 20, 스포츠 18, 지방의원 14 …)
+ **뉴스 언급**(0~35: 기사 색인 언급 수, 60일 반감 + 과거 블랙박스 기록 수) + **관심도**(0~20: 위키 언어판 수, 검색량 대용)
+ **관계 중심성**(0~10: 출처 있는 사람↔사람 관계 1점, 모임 소속 0.25점).
- 기준: 1계층 40점, 2계층 12점. **승격은 즉시**, **강등은 기준보다 8점 낮은 상태가 2주 연속**일 때. 1계층은 승격 후 90일 보호, 현직은 강등 없음.
- 상한: 1계층 30,000명, 2계층 150,000명(`TIER1_CAP`, `TIER2_CAP`). 넘으면 기준점을 자동으로 올림.
- 명부에서 빠진 사람도 지우지 않음(`gone`). 모든 승격·강등은 `db/people/tiers/log/YYYY-MM/*.jsonl.gz`에 추가만 함.

## 5. 관계 (`edges.py`, 매주)
- 유형 `t`: `family` 가족 · `school` 학연 · `region` 지연 · `career` 경력·조직 · `party` 정당 · `case` 사건·법원.
- 가족·사건은 사람↔사람, 나머지는 사람↔모임(`g:<유형>:<이름>`) 소속으로 저장(같은 학교 전원을 서로 잇지 않음).
- 모든 관계에 `src`(출처 주소)·`conf`(신뢰도)·`via`(어디서 왔는지)·`first`/`last`(처음·마지막 확인일). 신뢰도: 국회 0.95, 위키데이터 가족 0.9·기타 0.85, 판결 보도 0.6~0.7, 제미나이 관계망 0.4~0.5.
- **공개 조건**: 양쪽이 1·2계층(모임이면 사람 쪽), 출처 주소 있음, 가족이면 미성년자 없음. 못 미치면 `pub=0`으로 보관만 함.
- 출처: 위키데이터(1·2계층 국내 인물, 30일마다 순환, 회당 6,000명), 국회(정당·선거구), 판결 보도(판사↔법원·변호인), 제미나이 `elite_network.json`(학연·지연·연수원 기수·MCN·조직). 제미나이 자료는 지우지 않고 읽기만 한다.
- 사라진 관계도 지우지 않고 `gone` 날짜를 달아 둔다. 변경은 `db/people/edges/log/`에 추가만 함.

## 6. 화면의 공개 범위 (`assets/app.js` `peoplePrivacyGate`)
- 사이트는 `data/people_public.json`(1·2계층 이름 `t1`·`t2`, 공개 가능한 가족 쌍 `fam`)을 읽어 관계도를 거른다.
- 가족 노드는 **두 사람 쌍**(`fam`의 "이름A|이름B")이 출처 있는 공개 가족 관계(위키데이터 등, 양쪽 1·2계층, 미성년 아님)일 때만 보인다. 이름 하나로 판단하면 흔한 이름의 동명이인이 남의 가족으로 공개되기 때문.
- 가족이 아닌 사람 노드는 `t1`·`t2`에 있어야 보인다. 파일을 못 읽으면 가족 노드는 숨긴다(닫힌 쪽으로 실패).
- 3계층 가족·지인의 인물 문서 자동 생성(`getOrSynthesizeDossier`)은 하지 않는다.
- 이름이 같은 노드는 고정 id 노드 하나로 합친다(`dedupePeopleByName`). 제미나이의 이름 기반 자료(`MASTER_RELATION_NETWORKS`·`elite_network`)는 그 뒤에 덧붙는 보조 자료다.

## 6-1. 고정 id 관계도 (11.11, `scripts/people/graph.py` → 사이트 `data/graph/`)
- `people-tiers`가 매주 `db/people/edges/public.json.gz`(출처 있는 공개 관계)로 조각을 만든다: 이름 조각 `n/NN.json.gz`(이름 → 같은 이름 1·2계층 인원 `c`, 관계가 있는 후보 `x`), 관계 조각 `e/NN.json.gz`(id → 관계·같은 모임 상위 3명·상대 이름). NN = sha1 앞 6자리 % 64. 합계 약 3MB(gzip, 화면이 `DecompressionStream`으로 풂).
- **중심 정하기(동명이인 방지)**: 국회 id가 있으면 그 사람(`pol:` 또는 같은 사람으로 묶인 `wd:`), 없으면 그 이름의 1·2계층 인물이 **딱 1명**일 때만. 둘 이상이면 고정 id 관계는 안 붙인다.
- **같은 사람 묶기**: `pol:`(국회)과 `wd:`(위키데이터)가 이름·정치 분야·출생연도 ±1년으로 딱 1명 맞으면 합침(11.11 기준 1,170명).
- 화면 분류: 가족→직계, 학교→학연, 출생지·지역구→지연, 직위·소속→정무·직무, 정당→정치, 재판→시민사회. 모임(학교·지역·기관)은 그 자체가 노드이고, 학교·출생지·기관·팀에는 같은 모임의 상위 인물 2명까지 '동문·같은 고향' 으로 붙인다(정당·직위는 너무 커서 제외).
- 가족 방향: 위키데이터 문서 주인(출처 주소의 Q번호)을 기준으로 '부친·모친·자녀·배우자·형제자매'를 정함. 방향을 모르면 '가족'.
- 숫자(11.11 12:32 KST): 이름 14,119 · 관계 있는 인물 17,515 · 관계 55,490.

## 7. 외부 링크 점검 (`linkcheck.py`, 매일 04:40)
- 대상: 인물사전 출처 기사, 뉴스에서 찾은 인물의 기사, 판결 보도, 프로필 사진 원본, 위키데이터 문서. 우리 사이트·구글뉴스 중계 주소·홈페이지 자체 주소는 제외.
- 주기: 주소 해시로 날짜를 나눠 **1·2계층이 참조하면 14일, 3계층만 참조하면 30일**에 한 번. 위키데이터는 30일(하루 약 3천 건, 50개씩 묶어서). 일시 오류는 다음 날 재시도(`retry.json`).
- 예의: 호스트마다 2초 간격·동시 1건, 회당 최대 2,500건·25분, 이미지는 HEAD, 문서는 앞 64KB만 GET, 사용자 에이전트에 사이트 주소 표시.
- 판정: 200 `ok` · 301/308 영구 이동 → **새 주소로 자동 교체**(`repaired`, 원래 주소는 `o`) · 302/307 `redirect` · 제목 해시 변화 `changed` ·
  404 1회 `missing` → 2회 연속(410은 즉시) `dead` · 깊은 주소가 홈페이지로 넘어가면 사실상 404로 봄 · 401/403/429/5xx/시간초과 `error`(재시도).
- 다시 찾기: 위키백과 넘겨주기, 위키데이터 병합(새 Q번호), 같은 출처의 https/www/모바일/AMP 변형 중 제목이 같은 주소 → `refound`.
- 해외 IP를 막거나 늦추는 국내 사이트(*.go.kr·*.or.kr·네이버·다음)는 GitHub에서 막히면 `geo`(미확인)로만 표시. 맥미니에서 `LINK_REGION=kr python3 scripts/people/linkcheck.py data legal`로 확인 가능.
- 저장: 현재 상태 `db/links/state/c<주기>-b<칸>.json.gz`(그날 칸만 다시 씀 → git 용량 증가 최소), 모든 점검 결과 `db/links/log/YYYY-MM/*.jsonl.gz`(추가 전용), 요약 `db/links/summary.json`, 위키데이터 상태 `db/links/wikidata_state.json.gz`.

1. 제미나이 `MASTER_RELATION_NETWORKS`(app.js)에 대통령 형제·자녀·처가 등 민간인 25명의 생년·직업·학교가 출처 주소 없이 들어 있음 → 공개 범위 필터로 가림. 자료 자체는 보존.
2. (11.11 사용자 결정·처리) `getOrSynthesizeDossier`·`MASTER_PEOPLE_DOSSIER`의 지어낸 보도·유튜브·블로그·공적기록 목록(실제 언론사 이름·날짜 사용) 18곳을 코드에서 지움. 인물 페이지 '관련 보도'는 `realPersonNews()`가 실제로 모은 기사(원문 주소 있음, 동명이인 거름)만 최대 8건 보여 주고, 없으면 섹션을 숨김. 남은 것: 관계·이력 카드의 출처 문구('학교생활기록부 공적 기록' 등 제미나이가 붙인 확인 안 된 출처 이름)는 그대로 → 정리 여부 결정 필요.
3. `people_bio.json`은 이름이 키라서 동명이인이 한 사람으로 합쳐짐(예: '민주당'이 인물로 들어감). 출처 표기 중 '학교생활기록부' 같은 확인 불가 출처가 있음.
4. (11.11 처리) `people_bio.json` 원본 73MB는 git에서 뺌(data/.gitignore). 압축본 `people_bio.json.gz`(5MB)만 git, 판본은 R2 `ledger/raw/people-bio/`(비공개). 사이트는 여전히 배포하지 않음(공개하면 `getOrSynthesizeDossier`가 7.9만 명 문서를 만들어 냄 → 사용자 결정 뒤).
5. `elite_network.json`(6.7MB)이 사이트에 공개됨: 의원 배우자 재산 요약 포함(국회공보 공개 자료지만 재게시), 범죄조직 인물 목록 포함.
6. (11.11 처리) 사진·썸네일은 R2(`docs/DATA.md`). media 브랜치·Pages에서 빠짐.

## 9. 수집 보강·정합성 순환 (2026-11-11부터)
- `coverage.py`는 매주 명부 전체를, 30분 수집 때는 변경분을 다시 세어 `db/people/coverage.json`과 `enrichment_queue.json`을 만든다. **명부 수·구조화 프로필 수·출처 URL이 있는 타임라인 수·검증 사진 수를 서로 다른 수치로** 기록한다. 구조화된 텍스트가 있어도 원문 URL이 없으면 `source_url_timeline`에는 포함하지 않는다. 정치인 사진은 `politicians` 공식 원장을 함께 읽고, 원장을 받지 못한 실행에서는 0명이 아니라 `data_available: false`(미확인)로 남긴다. 그래서 명부 1명이 곧 완성된 인물 페이지 1명으로 잘못 표시되지 않는다.
- 보강 큐는 1계층, 미성년 아님, 고정 `wd:Q…` ID 보유라는 세 조건을 모두 통과한 인물만 담는다. 이름만으로 검색하거나, 기사 대표사진을 초상으로 저장하지 않는다.
- `wikidata_backfill.py`는 같은 큐에서 매회 최대 18명의 직업·공직·소속·수상·공식 사이트를 Wikidata 원문 URL과 CC0 표기와 함께 `wikidata_facts.json`에 적재한다. 생년은 연도만 저장하며, 이 원장은 페이지에 자동 노출하지 않는다. 화면 반영은 인물 ID·현재 직무·원문 URL을 다시 대조한 뒤에만 한다.
- `portrait_backfill.py`는 매회 최대 12건만 처리한다. Wikidata `P18` 대표 이미지 → Wikimedia Commons 파일 → 라이선스 메타데이터 순으로 확인하고, 모두 통과한 파일만 720px WebP와 원본 파일명·저작자·라이선스·출처 URL을 `portraits.json`에 함께 기록한다. 미확인·동명이인·민간인·라이선스 누락 항목은 화면과 저장 대상 모두에서 제외하며 실패 항목은 14일 뒤에만 재시도한다.
- 운영 목표는 서로 겹치는 직군 목표를 합산하지 않는다: 1계층 완성 프로필 30,000명, 2계층 검증 프로필 150,000명, 국회의원 3,296명, 기자·앵커 5,000명, 공적 문화·연예 인물 10,000명, 공개 활동 크리에이터 3,000명. `people_coverage.json`은 공개 가능한 집계값만 제공하며 원시 보강 큐·개인 정보는 배포하지 않는다.
- 수집 순서는 **명부 확장 → 출처 검증 → 고정 ID 대조 → 이력·기사·사진 연결 → 품질 집계 → 재시도**다. 불확실한 자료를 채워 넣기보다, 누락으로 남기고 다음 검증 주기에 보강하는 것을 원칙으로 한다.

## 10. 1계층 인물 페이지·사진 (2026-11-11)
- 화면: `/news/person/?id=<id>`(1계층 5,532명, `nw:` 잡음 id 제외), 분류 `/news/e/?k=g:<유형>:<이름>` 또는 `kind:<분야>`. 옛 `entity/<이름>`은 이름이 한 사람으로 정해질 때(`data/p/names.json`, 점수 1.5배 이상 차이)만 인물 페이지로 넘김.
- 묶음: `scripts/people/person_pages.py data pol_db _site` → `_site/data/p/`(x 256조각·g 64조각, 약 26MB). `pages.yml`·`collect.yml`이 배포 때마다 만듦(커밋 안 함).
- 위키데이터 사실·사진: `scripts/people/wd_t1.py`(`people-photos.yml`, 매주 일 06:20 KST + 수동) → data 브랜치 `db/people/wd_t1.json.gz`·`photos_t1.json`, 사진은 R2 `people/pt/<hh>/<hash>.webp`(720px)·`_s.webp`(128px). 공용(Commons)에서 **자유 이용 허락(CC·퍼블릭 도메인·공공누리 등)만**, 128px 미만·비자유는 제외, 저작자·허락을 화면에 표기. 미성년(최근 19년 출생) 제외.
- 사진 우선순위: 위키미디어(R2) → 국회 공식(`data/pol/photos/`) → 검증 초상(`portraits.json`).
- 인물사전(`people_bio`) 사건: id 키 우선, 이름 키는 동명이인이 없을 때만. **선관위 당선인 명부 행은 그 사람의 알려진 정당과 다르면 버림**(id 키에도 동명이인 당선 기록이 섞여 있었음, 예: 진천군 의원 이재명).
- 생애 기록 제목은 두 명 이상 모인 학교·기관·직위·정당·소속·위원회 이름과 맞춰 분류 페이지에 연결하고 그 사람을 모임 구성원으로 넣음.
