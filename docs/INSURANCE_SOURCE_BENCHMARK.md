# 보험 원장 수집 벤치마크와 수집 전략

## 유사 서비스의 장점과 적용

| 서비스 | 장점 | 뉴스보드 적용 |
|---|---|---|
| 보험다모아 | 보험종목별 보험료·보장내용 비교와 가입 경로 | 상품·보험종목 표준 분류 |
| 금융감독원 파인/금융상품 한눈에 | 금융협회 공시와 회사별 소비자 정보를 한곳에 연결 | 보험사·상품·공시·민원·재무를 같은 ID로 연결 |
| 보험사 공식 공시실 | 판매중/판매중지 상품, 판매개시일, 약관·상품설명서 원문 | 가입시기 기준 약관 버전·개정이력 보존 |
| 손사인 약관 검색 | 상품명과 가입 연월로 당시 약관을 찾는 UX | 상품명 정규화 + 가입일 역조회 |
| 국가법령정보 공동활용 | 법령·판례·헌재·행정심판·법령해석의 목록/본문 연계 | 약관 조항-법령-판례-분쟁례 멀티홉 연결 |

## 수집·분석 순서

1. 공식 공시 페이지와 다운로드 원문을 원본 해시와 함께 보존한다.
2. JS 공시표는 페이지 후보를 먼저 저장하고 보험사별 API/렌더러 어댑터로 상품명·판매기간·파일 URL을 추출한다.
3. PDF는 `pdftotext`/`pypdf`를 우선 사용하고 텍스트가 부족한 스캔본만 `pdftoppm + tesseract(kor+eng)` OCR을 시도한다.
4. 문서종류, 상품명, 판매기간, 개정일, 보장·면책 조항을 구조화한다.
5. 버전 키는 `insurer_id + normalized_product_name + effective_from + effective_to + document_hash`로 고정한다.
6. 변경 감지 후에만 조항 비교·판례/분쟁례 매핑을 수행한다.

## 병목 자동 해결

- 후보 0건: 공식 페이지 자체를 `catalog_page` 후보로 보존한다.
- HTML에 표가 없음: 보험사 도메인별 브라우저/API 어댑터 큐로 승격한다.
- 이미지 PDF: OCR 결과·원본 해시를 함께 저장하고 낮은 신뢰도는 검토 큐로 보낸다.
- 과거 약관 부족: 판매중지 탭과 과거 다운로드 링크를 우선 순회한다.
- 중복 문서: SHA-256으로 동일 파일을 하나의 원문으로 병합한다.

`db/system/collection_inventory.json`은 보험사 수, 후보 링크 수, 실패 수, 부트스트랩 URL 수, 원문 수, 텍스트 추출 수, 구조화 약관 수를 분리 기록한다. 계획값은 완료량으로 표시하지 않는다.
