# 매일 편집 콘텐츠 운영 런북

이 문서는 4컷 만화와 카드뉴스를 **대화 세션이나 특정 에이전트가 사라져도** 이어서 만들기 위한 실행 기준이다. 자동 수집은 사실과 후보를 준비하고, 시각 제작은 근거가 고정된 작업 묶음만 이어받는다. 그래서 생성 한도·토큰 만료·작업자 교체가 콘텐츠의 사실성이나 화면 폴백을 망가뜨리지 않는다.

## 자동으로 남는 인수인계물

수집 워크플로는 `scripts/editorial_queue.py`를 실행해 `data/editorial/queue.json`을 만든다. 이 파일은 다음을 포함한다.

- 우선순위가 높은 최대 3개 이슈와 출처 링크
- 4단계 스토리 비트: **무슨 일 → 왜 발생 → 수치·근거 → 다음 검증 지점**
- 재사용할 자산이 있는지, 새 작화 전에 반드시 할 사실 검토
- 모델에 종속되지 않는 `visual_contract`: 패널 비율·캐릭터 연속성·대사 여백·금지 요소·수락 기준
- 다음 작업 명령과 완료 정의

`fun.py`도 같은 구조를 강제한다. 대본에 “원문을 확인하세요”, “지켜보자”, “이해가 쏙” 같은 빈말이 있거나 2컷의 원인·4컷의 구체적 후속 확인이 없으면 AI 대본을 버리고 근거 기반 규칙 대본으로 되돌린다. 숫자는 입력 기사 묶음에 있는 숫자만 쓸 수 있다. 장기 타임라인이 없는 당일 이슈도 **사건 → 원인 → 근거 → 다음 신호 → 출처** 카드 덱으로 만들며, 이 다섯 요소와 출처 수가 품질 게이트를 통과하지 않으면 배포하지 않는다.

## 매일의 작업 순서

1. `data/editorial/queue.json`에서 `status: ready_for_editorial_review`인 항목 하나를 고른다.
2. `sources`와 네 개의 `story_beats.evidence`를 읽어, 원인과 수치가 실제 출처에 있는지 확인한다. 애매하면 `needs_fact_review`로 남기고 제작하지 않는다.
3. 매일 최우선 후보 하나에는 맞춤 작화를 만든다. 큐의 `daily_caps`를 넘겨 만화나 카드뉴스를 양산하지 않는다(각각 최대 3개).
4. 시각 자산이 `reuse_existing`이면 그대로 사용한다. 새 자산은 `visual_brief`와 `visual_contract`를 함께 프롬프트의 근거로만 사용한다. Claude·Gemini·Grok·로컬 Apple 모델·사람 편집자 중 가능한 작업자가 같은 JSON을 이어받는다.
5. 작화는 상단 가로 1컷·가운데 분할 2컷·하단 가로 1컷의 4컷 구조를 기본으로 하며, 컷마다 소품·공간·카메라를 달리한다. 실제 인물·피해자·회사 로고를 사실 사진처럼 만들지 않는다. 이미지에는 읽을 한글이나 말풍선을 넣지 않는다. 말풍선과 대사는 웹에서 렌더링한다.
6. `assets/comics/YYYY-MM-DD-<slug>.webp` 또는 `assets/cards/YYYY-MM-DD-<slug>.webp`에 저장하고 `assets/editorial-art.json`에 **ID 또는 엄격한 제목 키워드 매칭**을 등록한다. 작화가 연결된 당일 만화·카드 덱은 수집 군집 ID가 바뀌어도 보존된다.
7. 아래 검증을 통과시킨 뒤 커밋한다.

```bash
python scripts/editorial_queue.py --validate
FUN_DATA=data FUN_AI_SEC=0 python scripts/fun.py
npm run validate
```

## 화면·대사 규칙

- 대사는 이미지 바깥 본문이 아니라 해당 컷 위 말풍선에 둔다.
- 말풍선은 독립 리더선이 아니라 카툰식 삼각 꼭지를 쓴다. 꼭지가 글상자 안으로 파고들지 않아야 한다.
- 기본 꼭지는 발화 캐릭터가 있는 쪽을 향하고, 드래그한 뒤에는 독자가 그림을 피하도록 위치를 결정할 수 있어야 한다.
- 독자가 내용이나 그림을 가린다고 느끼면 말풍선을 드래그해 옮길 수 있어야 하고, 두 번 누르면 기본 자리로 되돌아가야 한다.
- 마지막 컷은 원문으로 떠넘기지 않는다. 다음 공시·수치·절차처럼 독자가 실제로 검증할 신호를 하나 제시한다.

## 작업자 교체 / 토큰 만료

작업자는 채팅 기록 대신 이 세 가지를 열어 현재 상태를 판단한다.

1. `data/editorial/queue.json` — 무엇을 왜 만들지, 어떤 단계인지
2. `assets/editorial-art.json` — 어느 기사에 어떤 선별 작화가 연결됐는지
3. `data/fun.json` — 실제 공개 대본과 `quality` 게이트 결과

이미지 모델을 쓸 수 없으면 새 이미지를 억지로 만들지 않는다. `fun.py`가 안전한 SVG/기사 이미지 폴백과 근거 기반 대본을 계속 제공한다. 다음 에이전트는 큐를 다시 실행해 최신 데이터 기준으로 이어서 작업한다.

## 배포 일관성

`collect.yml`은 수집 직후 큐를 커밋한다. `pages.yml`은 배포 직전에 현재 공개된 `today.json`으로 `fun.py`를 다시 실행한다. 이중 처리로 `today.json`은 새 것인데 만화·카드뉴스는 이전 수집 차수인 상태를 방지한다. 배포 과정에서는 `FUN_AI_SEC=0`으로 두어 외부 모델 한도와 무관하게 같은 규칙 결과를 재현한다.
