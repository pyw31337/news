# 법률 데이터 API 발급·연결 매뉴얼

이 문서는 개인 학습·검토용 법률 아카이브를 확장하기 위한 설정 절차다. API 키는
저장소에 직접 넣지 않고 GitHub Actions Secrets에만 저장한다.

## 비용과 이용 조건

- 국가법령정보 공동활용 Open API: 법령·판례·헌재결정례·법령해석례·행정심판례의 목록/본문은 국가법령정보센터의 `LAW_OC` 하나로 호출한다. 별도의 `DATA_GO_KR_KEY`가 필요한 구조가 아니다. 다만 OC 활용신청·승인, 등록 IP/도메인, 출처 표기와 이용조건은 지켜야 한다.
- 공공데이터포털 Open API: 국가법령정보센터의 동일 자료를 공공데이터포털 경유로 사용할 때의 보조 경로다. 개별 데이터셋의 `비용부과유무`가 무료여도 데이터셋별 활용신청, 서비스키, 일일·초당 호출량이 적용된다.
- 무료라는 뜻은 무제한이라는 뜻이 아니다. 한도 초과·키 만료·접근권한 정지 시 수집기는 원문을 삭제하지 않고 다음 회차 재시도 상태로 남긴다.

## 1. 국가법령정보센터 `LAW_OC`

1. [국가법령정보 공동활용](https://open.law.go.kr/)에서 회원가입한다.
2. 로그인 후 `OPEN API` → `활용신청`으로 이동한다.
3. API 인증키(OC)를 직접 지정한다. 영문 아이디 형태를 권장한다.
4. 시스템명에는 `NewsBoard 개인 법률정보 아카이브`, URL에는 실제 운영 주소를 입력한다.
5. 활용 목적에 다음을 기재한다.
   - 개인 학습·검토용 법령·판례·행정심판례 아카이브
   - 법령 시행일·개정 이력·판례 요지·행정해석을 출처와 함께 분류
   - 자동 법률자문·대리·유료 법률사무 제공 목적이 아님
6. 필요한 범주를 선택한다. 아래 범주는 모두 국가법령정보 공동활용에서 제공되는 실제 API 대상이다.
   - 현행 법령 및 법령 이력
   - 행정규칙
   - 자치법규
   - 판례
   - 헌재결정례
   - 법령해석례
   - 행정심판례
   - 조약·법령용어·별표·서식
7. 신청 승인 후 `마이페이지` → `API인증키관리`에서 OC를 확인한다.
8. GitHub 저장소의 `Settings` → `Secrets and variables` → `Actions`에서 다음 Secret을 추가한다.

   - 이름: `LAW_OC`
   - 값: 발급한 OC

## 2. 공공데이터포털 `DATA_GO_KR_KEY` (보조 경로만)

핵심 법률자료 수집에는 위 `LAW_OC`만으로 충분하다. 공공데이터포털 키는 아래처럼 별도 메타데이터·기관별 보조 API를 붙일 때만 필요하다.

1. [공공데이터포털](https://www.data.go.kr/)에 회원가입·로그인한다.
2. 필요한 데이터셋만 각각 활용신청한다. 우선순위가 높은 공식 항목은 다음과 같다.
   - [법제처 모바일 판례 목록 조회(15059404)](https://www.data.go.kr/data/15059404/openapi.do)
   - [법제처 헌재결정례 목록 조회(15057491)](https://www.data.go.kr/data/15057491/openapi.do)
   - [법제처 행정심판례 목록 조회(15056915)](https://www.data.go.kr/data/15056915/openapi.do)
   - [법제처 모바일 행정심판례 목록 조회(15058172)](https://www.data.go.kr/data/15058172/openapi.do)
   - [법제처 모바일 법령해석례 목록 조회(15056811)](https://www.data.go.kr/data/15056811/openapi.do)
   - 기관별 법령해석·위원회 결정문은 필요한 분야만 추가한다.
3. 데이터셋 상세 페이지에서 `활용신청`을 누른다. 위 공식 목록 데이터셋은 무료·개발단계 자동승인으로 표시되지만, 서비스별 승인/트래픽 조건을 최종 확인한다.
4. 개발계정으로 신청하고, 승인 후 `인증키`를 확인한다.
5. GitHub Actions Secret을 추가한다.

   - 이름: `DATA_GO_KR_KEY`
   - 값: 공공데이터포털 서비스키

6. 데이터셋별 API URL은 키를 코드에 하드코딩하지 않고 `legal/v1/state.json`의
   `dgk_endpoints`에 서비스명과 `{key}` 자리표시자를 넣어 관리한다.

```json
{
  "dgk_endpoints": [
    {
      "name": "행정심판",
      "url": "https://apis.data.go.kr/...?...&serviceKey={key}&pageNo=1"
    }
  ]
}
```

## 3. 연결 확인

GitHub Actions에서 `legal.yml`을 `workflow_dispatch`로 한 번 실행한다. 확인할 항목:

- `legal/v1/runs.json`의 `law.go.kr.reachable`
- `legal/v1/runs.json`의 `data.go.kr` 엔드포인트별 상태
- `legal/v1/index.json`의 `lawgo.prec`, `detc`, `expc`, `decc`
- `legal/v1/coverage.json`의 범주별 `current`, `coverage_pct`, `remaining`

키가 없거나 승인되지 않은 엔드포인트는 실패를 성공으로 바꾸지 않고 로그에 남긴다.
