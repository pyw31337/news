## 1. 3분 안에 이어받기

1. 동기화한다: `git fetch origin --prune && git switch main && git pull --ff-only`.
2. 최근 코드 기준을 확인한다: `git log --oneline -8 origin/main`.
3. 이번 회차의 실제 누적 데이터는 `origin/data:db/people/coverage.json`, `origin/data:archive/YYYY-MM-DD.json`, `origin/data:runlog.json`에서 읽는다. `today.json`은 배포용 최신 스냅샷이라 data 브랜치에 영구 보관하지 않는다. 화면의 숫자만 보고 판단하지 않는다.
4. 작업을 시작하기 전에 이 문서의 **금지 규칙**과 `docs/PEOPLE.md` 2·5·6·8·9절을 읽는다.
5. 데이터·화면·워크플로 중 무엇을 건드리는지 커밋 메시지와 PR/작업 설명에 명시한다. 서로 같은 원장을 동시에 재생성하지 않는다.

## 2. 제품과 데이터의 방향

NewsBoard는 단순 기사 목록이 아니라, 오늘의 이슈를 **기사 원문 → 시간 흐름 → 인물·기관·장소 → 과거 기록 → 시각 정보**로 연결하는 뉴스 보드다.

- 국내와 해외의 기본 표기는 한국어다. 해외는 같은 데이터에서 `해외(국문)`과 `해외(영문 원문)`을 전환한다.
- 화면에는 신뢰 가능한 사실과 원문 링크만 보인다. 빈 부분을 AI 문장·가짜 기사·가짜 경력·임의 초상으로 채우지 않는다.
- 텍스트만 늘어놓지 말고 시간축, 비율, 차트, 지도, 아이콘, 실제 사진·로고처럼 **출처가 확인되는 시각 요소**로 맥락을 보여 준다.
- 비용은 무료 티어를 넘지 않는다. 대량 원본은 `data`/R2, 개인 동기화는 D1 예산 안에서 diff upsert로 처리한다.

### 현재 속도와 현실적인 목표

- 자동 사실 보강은 회차당 최대 18명, 초상 보강은 최대 12명이다. 매 30분 회차가 계속 성공한다는 **이론상 상한**은 하루 각각 864명·576명이다.
- 현재 고정 QID를 가진 1계층 후보는 약 2,038명이다. 첫 회차 18명/12명을 제외하면, 현재 후보 풀만 처리하는 이론 최저는 사실 약 2.4일, 초상 약 3.5일이다. Commons 사진·라이선스 부재·14일 재시도는 포함하지 않았으므로 실제 초상 완료는 더 길 수 있다.
- 1계층 목표 30,000명에는 아직 24,418명, 2계층 목표 150,000명에는 83,418명이 남아 있다. 현재 QID 후보만으로는 1계층 목표를 채울 수 없다. 명부 확장과 고정 ID 확보율을 먼저 측정한 뒤에만 기간을 예측한다.
- 직전 첫 회차가 정치권에 쏠렸던 문제는 `00a9989fd3`에서 수정했다. 이후 큐는 정치 → 언론 → 연예 → 문화 → 경제 → 법조 → 스포츠 → 인플루언서 → 학계 → 기타 순환으로 섞는다.

## 5. 절대 지켜야 할 데이터·사진 규칙

1. **이미지를 생성하지 않는다.** 임의 뱃지, AI 얼굴, 기사 사진의 인물 추정, 이름 검색 결과를 초상으로 저장·표시하지 않는다.
2. 사진은 `고정 ID → Wikidata P18 → Commons 파일 → 라이선스/저작자/원본 URL`을 모두 확인할 때만 WebP로 보관한다. 얼굴이 실제 인물과 맞는지 사람이 검토할 수 없는 경우에는 표시하지 않는다.
3. 인물 이름만으로 동명이인을 합치지 않는다. 현직 대통령·국회의원·기자 등은 ID, 생년/직무, 공식 출처를 대조한다. 이재명은 현직 대한민국 대통령이라는 현재 직무가 상단의 다른 과거 이력보다 우선해야 한다.
4. 기사 제목·경력·수상·가족·관계·성향 분석을 생성하거나 추정해서 채우지 않는다. URL이 있어도 그 URL이 해당 주장 전체를 뒷받침하는지 확인한다.
5. 3계층·미성년자·민간인은 사진 저장과 공개 관계도 대상이 아니다. 가족·사생활·범죄 관련 추정 연결은 출처가 있어도 공개 조건을 다시 검토한다.
6. `people_bio.json`, `elite_network.json`, 기존 손수 넣은 `assets/people/`은 **검증 전 원시 자료**다. 지우거나 대량 공개하지 말고, 출처를 다시 대조한 뒤 ID 단위로 옮긴다.
7. 사실 원장과 화면용 요약을 분리한다. `wikidata_facts.json`과 `portraits.json`이 존재한다는 이유만으로 페이지에 자동 표시하지 않는다.
8. 비밀값·토큰·사용자 식별값은 문서, 커밋, 로그에 절대 넣지 않는다. 변수 이름과 등록 위치만 쓴다.

## 6. 다음 에이전트의 실행 순서

### A. 먼저 확인할 운영 상태

```bash
git fetch origin --prune
git log --oneline -8 origin/main
gh run list --repo pyw31337/news --workflow collect-news --limit 5
git show origin/data:db/people/coverage.json | jq '{registry, tiers, portraits, wikidata_facts, journalists, politicians}'
git show origin/data:archive/$(TZ=Asia/Seoul date '+%F').json | jq '{date, updated, issues:(.issues|length), trends:(.trends|length)}'
git show origin/data:runlog.json | jq 'if type == "array" then .[-1] else . end'
```

- `scripts/tier_manager.py`는 현재 사용자의 미추적 파일이다. 스테이징·수정·삭제하지 않는다.

### B. 현재 최우선 작업

1. **다음 수집 회차 검증**: 수정된 커버리지 집계가 정치인 원장을 읽고, 큐가 10개 분야를 라운드로빈하는지 확인한다.

3. **인물 렌더러 연결**: 검증된 ID·현재 직무·출처·사진 메타데이터만 읽도록 작은 읽기 전용 어댑터를 만든 뒤, 소수 인물로 매칭 검수를 한다. 대량 노출보다 오매칭 0건이 우선이다.
4. **기자 보강**: Mac mini 한국 IP 결과가 6시간 이내인지 점검하고, 기자 탭에 실제 `D.reporters`가 표시되는지 확인한다. 기자 기사·이직·수상은 각 항목마다 원문을 가진 경우만 노출한다.
5. **수집 확장 전 품질 지표**: 분야별로 `명부 / 고정 ID / 원문 연결 이력 / 라이선스 검증 초상 / 페이지 표시 승인`을 별도 집계한다. 목표·기간은 이 전환율이 여러 회차 쌓인 뒤에 갱신한다.

## 8. 화면·디자인 작업 시 맥락

- 사용자는 텍스트 상자 중첩을 싫어한다. 같은 종류 정보는 같은 포맷, 구분선·미세한 배경 차이·차트로 리듬을 만든다.
- 모바일은 3열을 억지로 유지하지 않는다. 6 → 4 → 2 → 1열로 적층하고, 글이 과도하게 줄바꿈되지 않게 한다.
- 화제는 최대 6개를 고정 그리드로 보여 준다. 사람·기업·장소·기관은 당일만이 아니라 최근 화제까지 유지하되, 썸네일은 실제 대표 사진·로고·국기·랜드마크에 한한다.
- 관계도는 컨테이너에 맞춰 노드와 간격을 가변 조절한다. 기본은 정적인 선이며, 롤오버/터치한 관련 노드에만 점 이동을 보여 준다.
- 접근성은 WCAG 기준의 대비·글자 크기·키보드 포커스를 지킨다. 카드 한 장만 유독 큰 제목으로 균형을 깨지 않게 한다.

## 9. 함께 일하는 에이전트 간 기록 방식

작업을 끝낸 에이전트는 다음을 커밋 설명 또는 이 문서의 “최근 작업”에 남긴다.

1. 변경한 **코드/워크플로/원장 경로**와 원인을 한 문장으로 쓴다.
2. 전후 숫자는 지표의 뜻을 붙여 쓴다. 예: `검증 Commons 초상 12 → 24명`처럼 쓰며, `인물 24명 확보`처럼 뭉뚱그리지 않는다.

5. 다른 에이전트의 원본을 삭제·정규화·공개하기 전에는 `git log --since='2026-11-01' --all -- <path>`와 최신 데이터 구조를 확인한다.
