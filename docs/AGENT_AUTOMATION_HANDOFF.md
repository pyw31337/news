# NewsBoard 자동화 공동 인수인계 계약

> 이 문서는 Codex, Claude, Gemini, Grok, 로컬 에이전트가 수집·분석·품질 자동화를 이어서 운영하기 위한 **단일 실행 계약**이다.
> 새 에이전트는 작업 전에 이 문서와 [`docs/AGENT_HANDOFF.md`](AGENT_HANDOFF.md)를 읽고, 작업 후 이 문서의 상태·로그·미해결 항목을 갱신한다.

## 1. 정본과 변경 원칙

- 코드 정본: `main` 브랜치
- 누적 원장 정본: `data` 브랜치 (`archive/`, `db/`, `runlog.json`, `status.json`, `stats*.json`)
- 미디어 정본: `media` 브랜치와 Cloudflare R2. 원본은 append-only이며 기존 파일을 덮어쓰지 않는다.
- 국회 원장: `politicians` 브랜치
- 과거 백필: `history` 브랜치
- 배포: `.github/workflows/pages.yml` → GitHub Pages
- 수집·분석: `.github/workflows/collect.yml` → 결과를 `data`/`media`에 커밋한 뒤 Pages를 호출한다.
- 법률·기업 보강: `.github/workflows/legal.yml`(3시간)와 `.github/workflows/corporate.yml`(매일 04:30 KST)이 뉴스 배포와 분리된 후처리를 담당한다.
- 섹터별 현재량·속도·ETA: [`docs/COVERAGE_SIMULATION.md`](COVERAGE_SIMULATION.md)를 기준으로 보고한다.
- 법률 API 발급·연결: [`docs/LEGAL_API_SETUP.md`](LEGAL_API_SETUP.md)를 따른다. 키는 `LAW_OC`, `DATA_GO_KR_KEY` GitHub Secret으로만 관리한다.

같은 데이터를 여러 에이전트가 각자 재생성하지 않는다. 화면용 파일을 고칠 때 원장과 생성 스크립트의 관계를 먼저 확인하고, 수동 JSON을 정본처럼 커밋하지 않는다. 원문·사진·관계·경력은 출처가 없으면 비워 두며 추정으로 채우지 않는다.

## 2. 자동화 실행 순서

`collect-news` 한 회차는 다음 순서를 따른다.

1. 원문 수집: `scripts/collect.py`, 해외·SNS·날씨·시장·공식통계 수집기
2. 엔티티·미디어: `entity_assets.py`, `portrait_audit.py`, `og_backfill.py`, `media_r2.py`
3. 분석·보강: `enrich.py`, `global_news.py`, `global_ai.py`, `people/mentions.py`, `people/collect_bio.py`
4. 누적 원장: `db.py`, `archive_extra.py`, `dedupe.py`, `people/*`
5. 정합성: `sanitize_today.py`
6. 사건 흐름: `event_quality.py` → `data/event_quality.json`
7. 품질 게이트: `quality.py`, `editorial_queue.py`
8. 운영 지표: `status.py`, `stats.py`, `stats_detail.py`
9. `data`·`media` 커밋 → Pages 빌드·배포

보강 장치 신선도는 별도 `.github/workflows/macmini-watch.yml`가 매시 `reporters_local.json`과 `overlay/latest.json`의 heartbeat를 검사한다. 6시간부터 경고, 36시간부터 실패로 표시하며 원본은 삭제하지 않는다.

`event_quality.py`는 원본 기사를 삭제하지 않는다. 이슈별로 `continuity`, `continuity_quality`, 단계 누락, 직접 관련도, 중복 후보를 별도 산출한다. 품질 점수가 낮거나 시작 단계가 비면 `editorial_queue`가 `needs_fact_review`로 표시한다. 이 표시는 실패가 아니라 검토가 필요한 사실을 숨기지 않는 안전장치다.

## 3. 에이전트별 작업 경계

| 작업 | 허용 정본 | 금지 사항 |
|---|---|---|
| UI/접근성 | `index.html`, `assets/`, `v2/`, `docs/design-system.md` | 수집 JSON을 화면에서 임의 보정하지 않기 |
| 수집/분석 | `scripts/`, `.github/workflows/`, `data` 산출물 | 기존 원장 삭제·날조·출처 없는 합성 |
| 인물/관계 | `scripts/people/`, `docs/PEOPLE.md`, `politicians` | 이름만으로 동명이인 병합, 사생활 추정 |
| 사진/로고 | `portrait_*`, `wd_media.py`, R2/media | AI 얼굴·임의 로고·라이선스 없는 저장 |
| 품질 | `event_quality.py`, `quality.py`, `editorial_queue.py`, `docs/QUALITY.md` | 점수만 올리기 위해 근거·누락을 제거 |

작업을 시작할 때 `git fetch origin --prune`, `git status --short`, 최근 `git log --oneline -10`을 확인한다. 커밋 메시지에는 영역과 결과를 쓴다(예: `fix(quality): mark missing episode stages`). 동시 작업이 의심되면 먼저 최신 `main`을 fast-forward하고, 충돌을 수동 해결한 뒤 검증한다.

## 4. 상태 확인 명령

```bash
# 코드·워크플로
git fetch origin --prune
git status --short
gh run list --workflow collect.yml --limit 5
gh run list --workflow pages.yml --limit 3

# 공개 산출물
curl -fsSL https://pyw31337.github.io/news/data/status.json
curl -fsSL https://pyw31337.github.io/news/data/stats.json
curl -fsSL https://pyw31337.github.io/news/data/stats_detail.json
curl -fsSL https://pyw31337.github.io/news/data/event_quality.json

# 로컬 정적 검증
npm test
python3 -m py_compile scripts/event_quality.py scripts/quality.py scripts/editorial_queue.py
```

운영 판단은 화면이 아니라 `runlog.json`, `status.json`, 워크플로 로그, `event_quality.json`을 함께 본다. `today.json`은 최신 배포 스냅샷이고 누적량 판단은 `archive/`와 `db/`를 기준으로 한다.

## 5. 장애·재시작 절차

1. 실패한 회차의 `gh run view <id> --log-failed`를 저장하고, 실패 단계와 외부 API 응답을 기록한다.
2. 원장·미디어 브랜치에 이미 커밋된 산출물은 되돌리지 않는다. 다음 회차가 재시도하도록 원인만 수정한다.
3. 네트워크·무료 티어 한도 문제면 수집 속도를 낮추거나 로컬 큐/R2에 보관하고, 누락을 성공으로 표시하지 않는다.
4. 분석 단계가 실패해도 원문 수집과 원장 보존은 계속한다. `event_quality`의 `gaps`, `evidence_rate`, `duplicate_candidates`를 남긴다.
5. 복구 후 `npm test`, 해당 스크립트 문법 검사, 수동 workflow 1회, Pages HTTP 200을 확인한다.

## 6. 현재 운영 판정 (2026-11-17 KST)

- `collect.yml`은 30분 주기와 일일 심층 회차가 설정되어 있다. 2026-11-17 13:42 KST 수동 회차(`44018982176`)가 확인 시점에 `enrich` 단계로 실행 중이며, 직전 회차 `44015347974`, `44012037278`, `44008482782`, `44004906997`은 모두 성공했다.
- `pages.yml` 최근 성공 배포는 `44017094802`이며, `https://pyw31337.github.io/news/data/event_quality.json`이 HTTP 200으로 공개되고 있다.
- 따라서 **수집·분석·품질 장치는 작동 중**이다. 단, 실행 중인 회차는 완료 전까지 최종 성공으로 간주하지 않는다.
- 공개 운영 지표(13:22 KST 스냅샷)는 최근 24시간 수집 49회, TOP10 요약 100%, AI 분석 100%, 사건 흐름 100%, 분류 신뢰도 84.3%, 썸네일 80.9%, 언론사 로고 89.1%, 해외 번역 41.7%다. 낮은 번역·미디어 지표는 자동화가 멈춘 것이 아니라 외부 원문/이미지·번역 한도 또는 근거 부족으로 보류한 값이다.
- `status.json`의 Mac mini 보강 산출물은 마지막 갱신이 2026-11-13 17:01 KST(약 92시간 경과)다. 본 수집 파이프라인과 분리된 로컬 기자·인물 보강 장치이므로, 다음 점검에서 LaunchAgent 로그와 `reporters_local.json` 갱신 여부를 별도로 확인한다.
- 번역·이미지 누락은 `status.json`의 `global_translate`와 `global.json.images`를 원인과 함께 본다. 429/403/401/timeout은 재시도·백필 대상으로 남기며, 원문이 없거나 robots가 거부한 이미지는 성공으로 위장하지 않는다.
- 공개된 사건 품질 산출물은 사건별 품질 점수와 누락 단계를 표시한다. 예를 들어 세무사 에피소드의 `gaps`에 최초 합격 발표가 남아 있으면, 시스템은 이를 감추거나 임의 기사로 채우지 않고 편집 검토 대상으로 보낸다.

### 8.3. 프론트엔드 연동 및 UI 개발 규칙
- **엔티티 링크 통일**: `assets/nbp/lib.js`의 `href.e(k)` 및 `href.g(k)`를 사용하여 모든 인물, 기업, 학교, 기수 칩이 상호 이동 가능하도록 구현 (`/e/?k=...`).
- **2-Hop 멀티홉 횡단 경로 표출**: `/e/?k=...` 진입 시 `[현재 엔티티] ➔ [1-Hop 노드] ➔ [2-Hop 노드]` 형태의 시각적 체인을 제공하여 데이터 간 자유로운 점프를 보장.
- **15개년 기업 일대기 블랙박스 타임라인**: 기업 상세 페이지 조회 시 15개년(2010~2024) 재무 시계열 바 차트, 창립~현재까지의 중대 사건 변곡점 타임라인, 사명 변천사, 역대 대표이사 계보를 시각화 도표로 표출.
- **11대 커뮤니티 민심 여론 모니터**: `admin/#pipeline`에서 11대 커뮤니티의 여론 온도 매트릭스와 실시간 뉴스 연계 버즈를 한눈에 관제.
- **로테크 양형기준 카드**: 형사/선거/기업 리스크 엔티티의 경우 대법원 양형위원회의 기본 권고형량, 가중/감경 영역, 집행유예율, 당선무효/임원결격 위험도를 배지와 게이지로 표출.

## 14. 고빈도 동적 vs 저빈도 롱텀 데이터 라이프사이클 관리 (Dual-Track TTL) (2026-11-17)

### 14.1. 데이터 성격별 이원화 분리 원칙
- 모든 데이터를 동일한 주기로 수집하는 것은 API 쿼터 고갈 및 시스템 자원 낭비를 초래함.
- **고빈도(동적) 데이터**: 실시간 발생 사건사고, 속보, 여론 등은 분/시간/일 단위로 기민하게 추적.
- **저빈도(정적 원장) 데이터**: 법률 판례, 보험 약관, 학연/지연, 기업일대기는 **초기에 바짝 전수 수집(Bootstrap Crawling)**을 완수한 후, 90~365일 단위의 롱텀 TTL을 적용하여 불필요한 반복 조회를 제거하고 변경 감지(Delta Verification)만 수행.
- **산출 원장**: `data/db/system/collection_lifecycle_matrix.json`

### 14.2. 트랙별 갱신 주기 매트릭스
1. **[Track A] 고빈도 실시간 동적 데이터 (High-Frequency / Hourly & Daily)**:
   - 사건사고 & 실시간 속보: 10분~30분 주기 / 일 2,400+ 건 / `archive/YYYY-MM-DD/` 자동 파티셔닝
   - 11대 커뮤니티 민심 여론: 매시 정각 (시간당 1회) / 감성 온도(-100~+100) 및 버즈 키워드 연산
   - 글로벌 멀티자산 & 거시 매크로: 장중 15분 / 마감 1일 1회 / 16개 핵심 지표 시계열 누적
   - DART 실시간 수시공시(8-K): 장중 1시간 주기 / 중대 공시(횡령/유증/영업정지) 발생 즉시 편입
2. **[Track B] 저빈도 정적 원장 데이터 (Low-Frequency / Long-term TTL 90~365일)**:
   - 법률서비스 렛츠로(Let's Law): 초기 15대 리딩 판례 완비 ➔ **90일 TTL** (대법원 선고문 증분 검증, 98.5% 리소스 절감)

## 18. 실측 진행률·확장 게이트 운영 규칙 (2026-11-18)

이전 문서에 적힌 완료율·완비 수치는 일부가 계획값 또는 seed 원장값과 섞여 있어 실제 수집 완료로 간주하면 안 된다. 에이전트는 `scripts/ontology/expansion_controller.py`가 데이터 브랜치의 파일과 레코드를 직접 세어 만든 `data/db/system/global_expansion_radar.json`만 진행률의 기준으로 사용한다.

- 90% 도달만으로 다음 국가·직군·속성을 활성화하지 않는다. `coverage >= 0.90`에 더해 품질 점수 `>= 0.85`, 공식 출처 필드, 최신성 검사를 모두 통과해야 `READY_TO_EXPAND`가 된다.
- `lawtech/precedents_db.json`과 `insu/policy_terms_db.json`에 공식 `source_url`/효력일이 없는 항목은 UI용 seed로 표시하며, 정상 원천 수집 완료로 보고하지 않는다.
- LAW_OC 법률 수집은 `.github/workflows/legal.yml`에서 3시간 주기로 계속 실행한다. 보험은 현재 스키마·seed 원장과 공식 출처 수집 큐를 분리하고, 보험사별 약관 원문 확보 전에는 완료율을 부풀리지 않는다.
- R2 원본·분석 보관은 `ledger.yml`, 인물 사진 WebP 업로드는 `people-photos.yml`이 담당한다. 새 수집기는 로컬 파일만 쌓지 말고 원본→분석→업로드 체크포인트를 남긴다.
- 미국·중국·일본·러시아 확장은 거래소/공시 원장과 이용 조건이 확인된 뒤 국가별로 순차 활성화한다. 인덱스 파일만 생성된 상태는 기업 전수 수집으로 간주하지 않는다.

## 19. 수집기 인수인계 원장

다른 에이전트가 같은 수집기를 중복 실행하지 않도록 온톨로지 회차마다 `scripts/ontology/collection_inventory.py`가 `data/db/system/collection_inventory.json`을 생성한다. 각 행은 실제 파일 증거, 수집 주기, 실행 워크플로, 현재 상태, 다음 병목을 포함한다.

| 영역 | 실행 경로 | 주기 | 현재 원칙 |
|---|---|---:|---|
| 법률 원문 | `.github/workflows/legal.yml` → `scripts/legal/collect.py` | 3시간 | LAW_OC 원문을 legal 브랜치에 누적하고 catalog로 범주·누락을 계산 |
| 판례·헌재·해석례 분석 | `.github/workflows/ontology.yml` | 매일 | seed를 보존하되 공식 source URL가 붙은 원문만 확장 게이트에 반영 |
| 보험 약관·분쟁례 | `scripts/insu/policy_terms_engine.py` | 매일 분석, 변경 감지 | 기존 공식 레코드를 보존하는 병합 방식이며, 보험사 공시 원문 확보 전에는 완료로 표시하지 않음 |
| DART 기업·임원·감사의견 | `corporate.yml`, `collect.yml` | 매일·장중 | `data/db/corps`와 `db/dart`의 실제 파일·공시 수를 기준으로 결측을 큐에 기록 |
| SEC 미국 기업 | `sec-market.yml` → `sec_snapshot.py` + `sec_detail_batch.py` | 일 100개사 배치·8-K 증분 | SEC 공식 티커를 갱신한 뒤 CIK submissions를 기업별로 저장하며, 인덱스만으로 완료 처리하지 않음 |
| 커뮤니티 | community source adapter | 1시간 | `data/community/posts` 원천 파일만 민심 분석에 사용하고 seed fixture는 별도 표기 |
| 인물·사진·로고 | `people-photos.yml` | 매일 증분, 대표 사실 주 1회 | 사진 매칭 후 WebP로 R2 업로드, 동일 시기 재수집 대신 장기 변화만 추적 |

보험 공식 원문은 `data/insu/source_manifest.json`에 `official: true`와 HTTPS 원문 URL를 등록한 항목만 `scripts/insu/source_adapter.py`가 수집한다. 예시 파일은 `scripts/insu/source_manifest.example.json`이며, 임의 검색 결과나 출처 없는 약관은 자동 거부한다.

이즈보험 약관 디렉터리(`dazabi.com/.../insurance_Terms.php`)는 2026-11-18부터 `scripts/insu/dazabi_catalog.py`로 보험사 공식 약관·상품공시 링크를 발견하는 보조 색인으로 사용한다. 현재 확인된 공식 링크는 32개이며, 발견된 링크는 기본적으로 `enabled: false`다. 담당 에이전트가 실제 상품목록·약관 다운로드 가능 여부와 이용조건을 확인한 뒤 개별 항목만 활성화한다. 디렉터리 자체의 설명이나 요약을 약관 원문으로 저장하지 않는다.

보험 6단계 파이프라인은 다음과 같다.

1. `dazabi_catalog.py`: 보험사 공식 공시 링크 발견
2. `official_catalog.py`: 승인된 보험사 페이지에서 상품·약관 후보 링크 발견
3. `source_manifest.json`: 담당자가 공식성·이용조건을 확인한 항목만 `enabled: true`로 승인
4. `source_adapter.py`: 승인된 원문만 다운로드하고 SHA-256·수집시각·Content-Type을 기록
5. `policy_contract.py`: 보험사·상품·판매기간·효력기간·근거 필드의 버전 인덱스 생성 및 가입자 로컬 입력과 근거 검색
6. `version_diff.py`: 원문 해시 변화 감지와 개정 로그 생성

초기 부트스트랩은 `bootstrap_fetch.py`가 공식 도메인에서 발견한 공개 문서를 회차당 최대 200개씩 수집하고 `bootstrap_checkpoint.json`으로 재개한다. 25MB 초과·비HTTPS·타 도메인·접근 제한 응답은 격리한다. 초기 색인이 끝난 뒤에는 URL별 SHA-256 변경 여부만 확인하는 증분 모드로 전환한다. 기본 갱신 정책은 판매중 상품·약관 변경 감지 일 1회, 판매중지·과거 버전은 주 1회, 전체 공식 링크 재탐색은 월 1회다.

가입자 보험 이력은 `data/insu/`나 깃에 저장하지 않는다. 사용자가 별도 로컬 JSON으로 제공한 경우에만 근거 검색을 수행하며, 결과는 원문 링크·효력기간·근거 필드와 함께 표시하고 지급 가능성이나 법률 결론으로 단정하지 않는다.

새 수집기를 추가할 때는 먼저 이 표와 `collection_inventory.json`에 고유 id·출처·주기·출력 경로를 등록한다. 기존 id와 같은 원장에 쓰지 말고, 원문(raw)·정제(clean)·분석(derived) 출력을 분리한다.

### 20.2. 서비스 간 온톨로지 연합 교류 프로토콜 (Federated Data Bridge)
1. **소비 방식**: 뉴스보드 등 타 서비스는 `scripts/federation_client.py` 및 `assets/federation_bridge.js`를 통해 로컬 우선(`../{service}/data/...`), 원격 배포(`https://pyw31337.github.io/{service}/data/...`) 하이브리드로 원장 데이터를 온디맨드 fetch한다.

3. **상세 아키텍처 명세**: [`docs/FEDERATED_ONTOLOGY_ARCHITECTURE.md`](FEDERATED_ONTOLOGY_ARCHITECTURE.md)를 정본으로 따른다.

### 21.2. 병목별 대체 경로

1. 공식 API 쿼터·승인 지연: 원문 URL와 요청 시각만 `source_candidates`에 적재하고 승인 후 delta cursor로 이어받는다.
2. 대용량 초기 수집: 국가·기관·기간별 샤드로 나누고 `checkpoint.json`을 남긴다. 실패한 샤드만 재시도한다.
3. 중복·동명이인: URN과 생년월일·소속·식별번호 복합키를 통과하지 못하면 `review_queue`로 격리한다.
4. 사진·로고 검증 지연: 원본 URL와 해시를 보존하고 매칭 통과분만 WebP/R2로 승격한다.
5. 로컬 저장공간 부족: 원본 스냅샷은 ledger/R2로 먼저 보관하고 분석 완료 후 TTL 정책에 따라 로컬 원본을 정리한다.
6. 국가 확장: 미국 SEC 완료 전 중국·일본·러시아를 동시에 열지 않고, 공식 원장·이용조건·언어 정규화가 준비된 국가부터 하나씩 활성화한다.

### 21.3. 회차 완료 판정

회차는 코드 실행 성공만으로 완료되지 않는다. 다음 세 산출물이 같은 회차 시각을 가져야 한다.

- `data/db/system/collection_inventory.json`
- `data/db/system/global_expansion_radar.json`
- 해당 도메인의 `checkpoint.json` 또는 catalog
