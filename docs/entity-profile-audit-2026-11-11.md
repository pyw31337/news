## 확인된 누락·정합성 문제

1. 이재명 생애 이벤트에 진천군 지방의원 선거 등 **동명이인/잘못 병합된 3건**이 섞였다. 이력 카드나 타임라인에 표시하기 전에 인물 식별자·선거구·소속·연도 일치 검증이 필요하다.
2. 풀 내 `type: person` 129명 가운데 실물 초상이 연결된 것은 73명이다. 일부는 장소·기관·일반명사가 사람으로 잘못 분류돼 있어, 사진 수집 전에 인물 판별을 먼저 해야 한다.
3. 관계망은 이재명 본인을 포함해 풍부하지만 다수 관계자의 `photo`가 비어 있다. 현재는 임의 문자 원형으로 대체될 가능성이 있다.
4. 2,950명 사람 레지스트리의 상당수는 `/entity/:name`으로 직접 진입할 수 있는 표준 레코드가 없다. 관계망에서 외부 포털로 빠지는 이유다.
5. 기관 심볼은 정당·일부 국회/대학을 코드로 그린 아이콘에 의존한다. `entity_media.json`에는 로고·장소 사진이 일부 있으나, 인물 경력의 기관명과 연결하는 정규화 키가 없다.

## 데이터 우선순위

1. **식별 정합성 게이트**: 위키데이터 QID 또는 공식 ID, 생년·직함·기간 중 2개 이상 일치할 때만 생애 사건을 합친다. 불일치 항목은 “검토 대기”로 격리한다.
2. **사람 마스터 레코드**: `person_id`, 정규 이름, 동명이인 구분, 사진·출처·라이선스, 공직/소속 이력, 관계, 기사 색인을 하나의 레코드로 묶는다. 모든 노드는 내부 `/entity/{person_id}` 링크를 갖는다.
3. **이미지·로고 자산 저장**: 공식·공개 라이선스 이미지만 받아 WebP 원본·320px·96px 파생본과 출처/라이선스/갱신일을 함께 보관한다. 외부 URL은 실패 시에만 사용한다.
4. **기관 정규화**: 기관명 별칭 → canonical ID → 공식 로고/심볼 → 출처의 흐름을 만들고, 문장 키워드 기반으로 임의 SVG를 만드는 방식을 단계적으로 제거한다.
5. **출처 등급**: 관보·선관위·국회·공식 기관(1차), 공신력 언론(2차), 위키/기타(보조)를 이벤트·관계·사진 각각에 표기한다.

## 제안 정보 구조

1. `지금의 인물` — 현직·공식 초상·오늘의 의제·데이터 기준 시각
2. `생애의 전환점` — 검증된 5–7개 전환점만 먼저 보이고 전체 연표로 이어짐
3. `공적 기록` — 선거·직무·입법/행정·재산·발언을 같은 행 단위로 표현
4. `관계의 지도` — 관계 유형·근거·신뢰도·사진을 같은 노드 문법으로 표시
5. `뉴스 아카이브` — 날짜·제목·언론사·맥락 요약을 한 행에, 중복 기사 묶음 지원

## 디자인 원칙

- 카드 외곽선의 반복을 없애고, `섹션 제목 → 얇은 구분선 → 행 단위 정보`로 읽는 리듬을 고정한다.
- 한 섹션 안에서는 날짜·기관·제목·출처의 위치를 절대 바꾸지 않는다.
- 큰 수치나 차트는 “무엇을 뜻하는가”와 같은 줄에 두고, 장식용 게이지는 줄인다.
- 사진은 공인·공개 라이선스·공식 이미지에 한정하고 출처를 남긴다. 없는 사람은 글자 배지가 아니라 중립적인 실루엣과 “사진 미확보” 상태를 사용한다.
- 모바일은 모든 2단을 세로로 쌓고, 관계망은 범주 필터와 탭으로 나눠 12개 이내 노드를 우선 노출한다.
